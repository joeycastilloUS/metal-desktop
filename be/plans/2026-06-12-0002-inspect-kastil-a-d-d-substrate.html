What It Is

Architecture Driven Development (ADD) — the single source of truth for all kASTIL Systems architecture. The human owns the design (CLAUDE.md files, skill.json manifests, folder structure); Claude implements exactly what the spec says and never invents APIs. Architecture flows from this repo into code trees via go.bat sync — a-d-d/ always wins on conflict.

Strict three-level hierarchy: intent (WHY — a deployable goal) → purpose (WHAT FOR — a capability) → skill (HOW — a focused pure-C library that composes upward). Claude's working scope is set by the directory it launches in (global / intent / purpose / skill).

the-last-test (tlt) — the tilde/test discipline

tlt is the second For-Rent service and the cleanest reference for how a tilde becomes a cloud-dispatched, sealed, metered operation. The load-bearing contract is the verb distinction, locked 2026-06-07 (the-last-test/CLAUDE.md):

  • ~t — the existing local browser-test tilde. Runs on the operator's box. No cloud, no meter. Unchanged.
  • ~tlt — the next-level verb for this For-Rent service. Cloud-dispatched, returns a sealed RunResult, fires a MeterEvent, emits a Signal. Anchored in kernel Quote #30.

Two sibling verbs; the operator picks per call. The four purposes draw hard boundaries — plan decides what runs, serve executes, meter counts, inspect observes — and none of them crosses another's job. That separation is the pattern worth stealing for a desktop tilde dispatcher.

POST /serve/run -> plan/queue -> plan/ready --[pass]--> serve/exec -> serve/seal -> meter/tally -> Signal
                                          \--[fail]--> plan/hide -> 200 {"status":"hide"}

Where the tilde system is actually specified

Key finding: the tilde system is not centralized in a single a-d-d spec. It is distributed:

  • Verb semantics live in the kernel CLAUDE.md (the metal repo), referenced from a-d-d as "kernel Quote #30" and "kernel § …". a-d-d points at the kernel; it does not restate it.
  • Distribution mechanism — nous/comms/skill/signals/CLAUDE.md defines Sealed-IDS Signals that carry tilde-completion events from emitters (metal.ce, metal.de) to listeners (jack-rabbit, tlt). The Signal struct carries char cmd[16] — the tilde, e.g. "~b".
  • Live state — GLOBAL.md board-status protocol: status.json schema v1 with currentTilde, itemTriple, boardId, phase, written atomically (.tmp+rename). The auto-board rule says every ~b and ~l re-renders the live board and pops it.
  • Reference renderer — metal/be/tools/render-board-view.py is named as the canonical implementation other intents copy.

So for metal.de: the verb table comes from the kernel; the wire-level contract (Signal struct + status.json) comes from a-d-d. Both are needed to implement tildes that interoperate with the rest of the Pantheon.
