~i~i — tilde system in metal desktop deep inspect

Second-order inspect: metal desktop edition (C:\metal-desktop) read against the a-d-d substrate (sibling ~i), to scope implementing the tilde system here more effectively and accurately than a first pass would. Goal: a real dispatcher, not slash-command theater.

What It Is

metal desktop is the browser cockpit of the metal product family — a pure-C HTTP + WebSocket server serving http://localhost:5050, rebranded from NOUS Desktop. Single-threaded select() event loop, cross-platform (winsock2 / POSIX), zero frameworks. Its strength today is provider fan-out: one question to many LLMs in parallel, then judge/summarize across the answers. Backend traffic rides the relay via the NTRP0001 wire protocol; provider calls go direct HTTPS.

Build: make (links ws2_32 / winhttp / bcrypt on Windows, pthread on Linux) → metal-desktop.exe. Config in desktop.conf (relay_host, relay_port, psk_file, listen_port=5050).

Launch note: metal-desktop.exe is blocked from Claude's sub-shell by the WDAC Application Control policy (same gate that blocks gcc). It must be started from Joey's interactive terminal — see "How to launch" at the foot of this report.

Input flow: user types in DISCOVER → on Enter the text is sent as {"type":"task","content":"…"}. A leading / only triggers a client-side autocomplete menu; the slash word is not parsed into a distinct message — it travels inside the task string. So even the slash commands aren't dispatched; they're cosmetic.

Gap Analysis — implementing tildes accurately

The seam is unambiguous: route_ws_message() @ serve.c:3056. Add one branch and a sub-dispatcher; do not touch the provider engine.

else if (strcmp(type,"tilde")==0) route_tilde(conn_id, msg);

Message schema (front-end → server): {"type":"tilde","cmd":"~i","args":"<text>","context":"<path>"}. The front-end change is small: in loop.js, when input starts with ~, send a tilde frame instead of folding it into task.

Do it accurately — lessons carried from metal-console

Lesson (from the kernel / a-d-d)How it applies here
Verb semantics are kernel-ownedDon't re-invent the tilde table. Lazy-load be/docs/commands.md as the spec source; the cockpit routes, the kernel defines.
Honor the wire contractEmit the a-d-d status.json v1 (currentTilde / phase / atomic write) and the Signal cmd[16] struct so jack-rabbit / tlt can listen. This is what makes metal.de a real Pantheon emitter, not a toy.
Separation of duties (tlt pattern)plan decides · serve executes · meter counts · inspect observes. A desktop dispatcher should keep "route" separate from "execute" separate from "report" — mirror the four-purpose boundary.
Two-verb discipline (~t vs ~tlt)Local vs cloud is an explicit operator choice, per-call. metal.de should expose both rails, never silently pick.
Slash ≠ tildeThe existing /judge etc. are provider-loop verbs; keep them. Tildes are workflow verbs. Don't conflate the two namespaces in one parser.
Pure-C, roll-your-ownNo template engine import. Reuse the inline HTML style these reports use; the Anthropic body builder already in serve.c is the LLM call path.

Suggested first move (smallest proof)

Wire ~h end-to-end first: front-end sends {"type":"tilde","cmd":"~h"}; server returns the help grid as a WS event; cockpit renders it. Read-only, no file access, no Signal — it proves the seam, the schema, and the round-trip in ~40 LOC. Then add ~i (read + HTML artifact), then a board-status write so the live board lights up. That sequencing matches the a-d-d auto-board rule without committing to the full agent-loop refactor up front.

Open Questions

  • Dispatch model: does metal.de execute tildes natively (spawn gcc/git, write files) or relay them to a metal-console agent? Native = a real refactor toward an agent tool-use loop; relay = thinner, keeps the cockpit as a front-end to the existing kernel. This is the load-bearing ~d decision before any ~b.
  • Prime dependency: ~i/~h/~l are local and need no prime. ~s/~store/Signal need the relay+prime path that's currently dormant (Board 6/7). Which tildes are in-scope for a no-prime v1?
  • Renderer: vendor render-board-view.py (Python dev-tool, fast) or write the C-native renderer (pure-C purity, more work)? a-d-d allows either if the status.json contract holds.
  • Signal conformance: need the Sealed-IDS v3.1 record-kind spec (under nous/security/) before metal.de can emit Signals other nodes will accept.
  • WDAC: the launch + any native build/exec steps are blocked from Claude's shell on this box. Tilde handlers that shell out will hit the same wall under automation — design for hand-off or relay, not silent local exec.
