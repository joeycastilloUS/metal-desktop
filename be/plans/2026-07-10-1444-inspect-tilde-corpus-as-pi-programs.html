1. What It Is

The metal Console Edition tilde grid is, read correctly, a corpus of 32 programs wearing conversation costumes. Each tilde spec in be/docs/commands.md is the transcript of a conversation Joey has had with Claude Code thousands of times — and every one of those runs left an artifact, a commit, a telemetry row, a Signal. The history is the source code of programs that already ran.

“.pi files are actually sealed-ids of pure intention that the biRT can execute. It's like a punch card where the machine reads the punches and does something.” —jc

This inspect treats the corpus the way Argus already treats a Zendesk thread (its ARCHITECTURE.md §6: “every conversation is a program … its .pi is its source; grammar's laws are what let the deterministic decoder read it”). For each tilde we separate the deterministic core (file I/O, git, JSON, template render, telemetry, Signal, board edits — the part that ports to C99 verbatim) from the judgment slots (the moments that genuinely need intelligence). The ratio is the tilde's LLM-free readiness. Note: ~jc was retired by the operator during this session (2026-07-10), removing the corpus's single irreducible-judgment pole; the remaining 32 all carry a substantial deterministic core.

3. Stack — what the corpus runs on

(a) One shared tail, not thirty-two

The single most important structural finding: the chain-reaction tail is one program, identical across every tilde — scaffold → save → index → telemetry-8-step → Latchkey → commit/push/backfill → DoD probes → Signal → pop. It is already half-ported to C99 (capture_prompt.c, otel_collector.c, build_site_telemetry.c, presence.c, src/latchkey/). It should be extracted once as biRT's tail executor. Each per-tilde .pi then collapses to: frontmatter (name / protocol / DoR-class / DoD-class / verb / model / sub_task_hints) + section-scaffold + judgment-slot list.

(b) The tier model already IS Cold/Warming/Hot

The Tiered Execution Chain design (C:\metal\be\designs\2026-06-07-1547-...) defines Tier 0 (pure C, $0), Tier 1 (C + per-op escalation), Tier 2/3 (LLM executor). Those tiers are the learned-routing temperature from the Tildes-Are-.pi canon: Hot = Tier 0, Warming = Tier 1, Cold = Tier 2/3. A tilde cools downward as its skeleton is discovered and sealed.

(c) The decoder is real and shipped

Joey's “decoder” is not to-be-built — it is nous understand(): pure-C99, WordNet 3.1, deterministic, $0, and cannot hallucinate (“it is only the words that were in the thread”). Argus already runs it as the REDUCE stage that turns text into a sealed .pi. Four of the five decode/replay stages already exist; only deterministic REPLAY (walk the .pi's action-units) is new.

(d) What already runs today

kastil-systems/tools r257 (C:\tools\metal-de, 301KB metal-de.exe) ships birt_tier0_l() and birt_tier0_ul() in pure C, stamped “Tier 0 execution. 0 LLM calls. 0 tokens. $0.00 cost.” Plus birt_fs.c (Read/Write/Edit/Grep/Glob, 46 green assertions), birt_loop.c, birt_translator.c (Anthropic only), relay_client.c, and the sdk/ primitives (wire.c NTRP0001, crypt.c Ed25519/AES/TOTP, http.c). The proof exists; it is just hardcoded C, not yet driven by a .pi file.

4. Patterns Found

  • Per-sub-task tiering, not per-tilde. The old tier map put ~jc at Tier 0; the extraction scored it ~5% judgment. The contradiction resolves one way: tier attaches to the sub-task, not the tilde. The shared tail is always Tier 0; each judgment slot carries its own tier. This is the correction the .pi frontmatter must encode (a slot list with per-slot tier), and it is the headline for the design.
  • Machine-verifiable tildes mature fastest. ~f's diagnosis is graded by a test that flips (fail→pass); ~e's sizing is graded by duration_sec already in telemetry. Their routing libraries warm on ground truth the IDS already holds — no new instrumentation. ~bt lacks such a flip, so it warms slowest of the mid-band.
  • Surface bindings are the per-tilde dispatchers. ~t → TLT (src/tlt/, vault/learned-tests/) is canon; ~chase → JR (the-jack-rabbit.net wire edge) is the purest (the surface is the whole tilde); ~brief → avatar-video, ~retro → dedicated reasoner, ~pt/~pu → TLT library follow.
  • Back-load vs forward-capture splits cleanly. Tildes whose history pairs input→output in the IDS (~e board+duration, ~u phrase→files, ~s diff→message, ~cr chain-position) can warm from git history today. Tildes whose judgment was never segmented (~d per-section, ~jc-style advice) need forward-capture of provenance from the next run onward.
  • The read-verbs are the decoder's proving ground. ~config, ~tag, ~h, ~patterns(read), ~l, ~li replay with no IDS query beyond their own file. ~h carries the strategic headline: metal already performed this exact extraction on it by hand — LLM-summarization was replaced by a deterministic h-cache render. It is both a sealed card and the precedent.
  • ~cr exists only because Claude Code sessions die without a program counter. Its whole forensic apparatus (fingerprint tables, break-point map) collapses under biRT to “read last sealed chain-state, jump to pc+1.” The board-status protocol is already that program counter, half-written.

5. Open Questions → the design's whitespace

Three things the corpus needs do not exist in code or design yet. These are exactly what the paired ~d answers, and they seed the board:

  1. The .pi format itself. Zero .pi files exist. Tier-0 today reads commands.md as its recipe and switches on a hardcoded if tilde=="l". Need: a frontmatter+scaffold+slot spec, a parser (data_access.c), and birt_dispatch() reading tier: from the card. (Master-plan P2, unstarted.)
  2. The decoder→dialect translator. birt_translator.c speaks only Anthropic. Need: one sealed .pi exported to a per-provider dialect on the fly — Joey's “.pi first, then export to model-specifics.” No design exists.
  3. Where Cold runs. “Escalate to the Pantheon” was never pinned to a host. Need: Claude-Code-in-Cloud-Run (clauderun, revived) as the Cold-phase discovery engine. The lock-ups that killed clauderun are the known TTY/headless hang — already fixed in the CliWorker variant.

Everything else (repo consolidation, the four organs, cross-platform HTTPS) is designed-and-queued in the parity plan, awaiting P0 approval.
