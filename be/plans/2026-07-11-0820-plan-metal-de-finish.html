Intent

Finish metal.de as a complete, usable, local-only application — an operator sits down, enters the passphrase, loads a real project, runs real tildes that produce real artifacts through the free providers, watches the live board, and gets a verifiable done — with zero dependency on relay, prime, or FQDN identity. Everything that needs the mesh is named, boarded, and parked behind an explicit un-defer trigger rather than silently blocking the finish line. Local done is THE done for this plan; the Mesh Horizon is the next plan's opening move.

Scope

In

  • Tier 1 — Local Done: flip the tail's fail-safe from observe to real mutation for a verified loaded project; artifact-producing (Cold) tildes running on the 5 free providers with the live tail shipping their output; the full local be/ machinery (board.md, board-status, telemetry, index, reports) with the live board view in the cockpit; the cross-platform floor (v2's B5 — Win/Mac/Linux build + run); real ed25519 card sealing with a local key (no relay ceremony); a local-done gate with receipts.
  • The passphrase gate (goodtimes) as the whole auth surface for this plan — hardened only to the extent of not weakening it (no bypass paths), not extended.
  • Rough Fibonacci points per board; ~e sizes each into triples after approval.

Out

  • Everything mesh: relay sessions, NTRP0001 into the substrate, prime deploy, Signal delivery off-box, catalog-over-wire (B2), relay-dependent tildes (B6), ~tlt metered runs (B7), A4 prime catalog emit, decode_ids nous headers. All boarded in Tier 2 as ⛔ deferred with named triggers — not forgotten, not blocking.
  • All identity: login, FQDN handshake, CF verify, TOTP, operator keystore, vault wiring (v2's B4). The passphrase is the interim contract until the Mesh Horizon opens.
  • B0 cross-org repo consolidation if it requires cross-org moves — local build discipline is already green; the org move waits for the org decision.
  • The full CE↔DE parity gate (v2 B8) — it requires the mesh legs; Tier 1 ships its own local-done gate instead.
  • New auth schemes, new catalog formats, frameworks, terminal tab, MCP, silicon console.

Approach

  1. Local done is a real done, not a consolation prize. Define it, gate it, verify it. An operator using metal.de daily on their own project at $0.00 is the product working — the mesh adds reach, not existence.
  2. The engine is already proven; finish the plumbing around it. The .pi parser, shared tail, sealed cards, and translator run on both editions from the same files. Tier 1 is not engine work — it is aiming the proven engine at a real loaded project and letting it mutate for real.
  3. Flip the guard, never remove it. The tail's fail-safe (default observe; mutate only an explicit, verified, non-engine project) is the safety contract. F1 widens the verified path; the default stays observe forever.
  4. Free providers are the Cold floor. The 5 loaded free providers carry every artifact-producing tilde in Tier 1. Paid escalation and metered For Rent stay out of scope; the mission stays $0-biased.
  5. Seal locally now, federate later. ed25519 signing lands in Tier 1 with a locally generated keypair on the operator's box. When FQDN identity arrives (Tier 2), the local key becomes the thing the identity ceremony attests — nothing re-built, only re-anchored.
  6. Defer loudly. Every Tier-2 board carries its un-defer trigger inline. When a trigger fires, that board moves to the top of the active queue — no re-planning required to resume.
  7. Plans are wrong by default. This is the v1 hypothesis of “the finish”; Unknowns and When To Revisit are first-class below.

Constraints the checklist

  1. Passphrase-only auth is the interim contract. goodtimes gates the cockpit; no login, relay, TOTP, or FQDN lands in Tier 1. No board may quietly introduce an identity dependency. Full identity is M3, operator-triggered.
  2. The tail's fail-safe guard is never weakened. Default is observe, always. Real mutation happens ONLY for an explicit, verified, operator-loaded non-engine project (F1's verified path). No board, fix, or convenience ever flips the default or widens mutation past the verified project.
  3. Zero mesh dependency in Tier 1. If a Tier-1 board discovers it needs relay/prime to exit, the board is mis-cut: re-scope it local or move it to Tier 2. Local done cannot wait on the mesh by definition.
  4. C99 everywhere we own; no frameworks. Vanilla HTML/CSS/JS in the cockpit; C# only as sanctioned foreign-API jackets. The engine stays the same files on both editions — no DE fork of parser/tail/translator.
  5. Done = externally verifiable where a real artifact exists (Rule 9). Local-only scope narrows the vantage, not the standard: fresh-machine build receipts, tamper-fail seal proof, a real commit in a real project's repo a third party can clone and see. Where an artifact has a published home, HTTP 200 or it isn't done.
  6. Free providers only in Tier 1. The 5 loaded free providers are the Cold floor; no paid escalation, no metered runs (that's M6).
  7. Local ed25519 key never leaves the box. Generated on first run, machine-anchored now, FQDN-attested later (M3). Key material never committed, never transmitted.
  8. Wire protocol only into Purcius when Tier 2 opens — never HTTP/REST/SDK into the substrate. Tier 1 touches the substrate zero times.
  9. Board + versioning discipline: triples, Fibonacci, verify-loop pairing (~a~t), Kaizen K-board; v0 · rN · date · pts; no co-author lines.
  10. a-d-d is human-owned (Rule 10); any spec change this work surfaces flows up as a proposal before code lands (Rule 11).
  11. Plan shape honored + this banner stays until approved.

Unknowns named explicitly

  • What “verified project” means precisely — F1's verification contract (explicit path pick? git-repo check? marker file? confirm prompt?) is undesigned. It must be strong enough to protect the guard and light enough to not annoy daily use. Settle at F1 start.
  • Free-provider reliability under real Cold load — the 5 free providers are loaded but unproven against full artifact generation (length limits, rate limits, refusal shapes). Fallback ordering may need tuning; a provider dropping to 4 or 3 changes F2's floor.
  • Cockpit board-view rendering path — CE renders board views via Python (render-board-view.py); DE's cockpit needs either a vendored equivalent or a C99-native render. Which one F3 ships is open (vendoring is the v2 precedent; native is the mission).
  • Mac/Linux build environments — no Mac or Linux box has built metal-de yet this cycle; toolchain surprises (signing, threading, TLS) land on F4. WDAC-under-automation on Windows remains the known CI gap.
  • ed25519 implementation source — roll from the C99 primitives in nous/crypt or vendor a single-file implementation? License + audit posture decides; no OpenSSL dependency either way.
  • Passphrase hardening line — “don't weaken” is clear; whether F6 requires rate-limiting/lockout on the gate before declaring local done is not. Decide at the gate.
  • Trigger observability — who notices when a Tier-2 trigger fires (prime deploys, specs publish)? No watcher exists; today it's the operator saying so. Cheap: a K-board item per trigger.
  • How much of B0 is actually needed locally — if the org move stays deferred, does any Tier-1 board trip over the current repo layout? Believed no (builds are green); F6's fresh-machine walk is the proof.

When To Revisit the v2 triggers

  • F1's verification contract can't be both safe and usable — if the verified-mutate path needs more than a light ceremony, the guard design (not the plan) is wrong: back to ~d before touching the tail.
  • Free providers can't carry a full artifact — if F2 can't land a real ~d/~p artifact on the free floor after fallback tuning, the $0 Cold premise re-opens and this plan needs a v2 with an escalation decision.
  • Any Tier-2 trigger fires — the moment prime/relay deploys, specs publish, or the operator lifts the passphrase lock, pull that M-board to the top of the queue and re-sequence forward of whatever is in flight. That is the Mesh Horizon opening, and it likely warrants the successor plan.
  • The operator asks for a second machine or a second operator — the passphrase contract is single-box by design; the first multi-box need un-defers M3 early.
  • F4 uncovers a platform fork in the engine — if cross-platform work forces divergent parser/tail sources, the same-files invariant is threatened: stop, flow up (Rule 11).
  • F6 fails its gate — the gap list becomes the next boards, not a silent shrug; two consecutive gate failures = plan v2.
  • Any drift between the a-d-d spec and implementation (Rule 11) stops the tilde and flows up; two stops in one board = plan v2.
