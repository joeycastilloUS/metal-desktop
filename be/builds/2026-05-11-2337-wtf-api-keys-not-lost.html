~wtf: API keys "lost" -- audit + permanent fix

Claim: "you lost all of my api keys, this happens quite often." Audit + root cause + plan to stop the bleeding.

The answer

I did not lose them. They were never on this machine.

The pattern repeats every time you open metal-desktop on a fresh box because users.dat (the file that holds your paid-tier API keys) is a per-machine, plaintext, gitignored-by-omission file. Never committed, never synced. It exists on maximus where you set it up; it doesn't follow you to neo or anywhere else.

The mental model that's wrong

You're treating "metal-desktop on neo" and "metal-desktop on maximus" as the same project state. They share git-tracked files (source, board, docs). They do NOT share runtime secrets:

The "9 free builtin" line in the server log confirms nous_keys_builtin.h exists with real keys -- because it was put there ONCE by hand at some point on neo (or copied) and never gitignore'd off. The paid keys (which go through users.dat) were never set up on neo.
