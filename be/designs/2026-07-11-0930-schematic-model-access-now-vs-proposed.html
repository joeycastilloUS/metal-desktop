✓ Key custody: one sealed vault on the prime fleet. BYOK rides the encrypted wire per-request, RAM-only; blank = internal key is the specified fallthrough — free tier with zero setup. Rotate a key once, in one place.

Placement honesty: v1 runs on the existing primes (Ashburn / Las Vegas / Singapore / Hong Kong). Provider-adjacent placement — a prime beside each model DC, as drawn — is the deferred ops play; the router gains a provider→prime affinity map when those nodes exist. The custody move does not wait for it.

The Diff

AxisNOWPROPOSEDWhy it matters
Key custody ⚠ On every box — users.dat, env, keys_builtin.h compiled into the binary (serve.c:358) ✓ Mesh vault only; BYOK per-request on the wire, RAM-only; blank = internal The whole security thesis. Ship the binary without shipping the secrets.
Transport Direct HTTPS from the operator's box to each provider API Wire over the mesh — 0xCA AES-256-GCM triples, cockpit → relay → prime Wire protocol only into the substrate — never HTTP. Relay is blind by design.
Front door Per-edition fan-out — every serve.c re-solves provider access One nous.api — four verbs (ask / judge / summarize / reconsider), api_dispatch on the prime One place to meter, rotate, and fix — or N copies of the same problem.
Placement Wherever the operator happens to sit — no control Prime beside each model DC (Anthropic/Ashburn, Google/us-central, …) Latency by geography — the last HTTPS hop is meters, so the mesh hop costs less than it saves.
Failure / offline N/A — the local path IS the only path Local fan-out demoted to offline/bridge fallback; relay unreachable → local keys still work The mesh is the default, not a hostage-taker.
Cost to get there Zero — it runs today 5 extraction boards N1–N5 · ~113 pts · ~2.5–3 wks Extraction, not invention — "fanout is handle_task minus the WebSocket I/O." The donor code exists.
