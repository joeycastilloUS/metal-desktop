Be ~d — The Extraction Engine Published 2026-07-10 14:44 PDT

The Extraction Engine foundational

Conversations → .pi → .ids → runtime dialect → biRT replay. Extract the intelligence under every tilde, restate it as sealed pure intent, and replay it on demand in pure C99 — renting an LLM only for the genuine Cold-phase discovery, hosted in clauderun. This design finishes what Tier-0 already proved.

This design EXTENDS proven work — the Tier model, the Tier-0 ~l/~ul engine (r257), nous understand(), gcp-bridge, and clauderun's CliWorker. It adds the three pieces that do not exist yet: the .pi format, the dialect translator, and the Cold-phase Cloud-Run host.

1. Need

The software factory that builds itself cannot run on a per-command LLM bill. CE proved the discipline over 1,875 revisions — but every tilde routes through Claude Code, so every deterministic step (re-walking the same 9-step chain, re-reading the same recipe) costs tokens and seconds. The receipt is exact: an LLM-driven ~ul ran 47.9s / $0.146 and didn't finish; the pure-C Tier-0 ~ul runs ~100ms / $0.00 and does. The ~i paired with this design showed the truth quantitatively: 6 of 32 tildes are 100% LLM-free today and 13 of 32 are ≥85% — yet none of that mechanism runs without a model in the loop, because the deterministic core has never been separated from the judgment and sealed as its own artifact.

What's missing is not the engine (Tier-0 exists) and not the decoder (nous understand() exists). What's missing is the artifact that makes tier a property of data, not of code — the .pi punch card — plus the two things that let it reach any model and run Cold work off-box: a dialect translator and a Cloud-Run Claude-Code host. Extract the intelligence, restate it as .pi, replay on demand. metal Desktop Edition becomes lightspeed and LLM-free by default, trickling in intelligence only at the genuine discovery edge.

2. Raw User Stories

  • As the operator, I want ~h ~l ~config ~tag ~li ~chase to run on my desktop at $0.00 in ~100ms, because the factory must not bill me for work that never changes.
  • As the operator, I want each tilde's intelligence sealed as a .pi punch card I own, so the recipe is sovereign data — not a prompt buried in a vendor's context window.
  • As the operator, I want the .pi exported to whatever dialect the target model speaks — Claude, Anthropic-on-Vertex, or the next model — on the fly. .pi first; model-specific second.
  • As the operator, I want Cold-phase discovery to run Claude Code inside Cloud Run (clauderun, revived), so the deep work happens off my box, keyless, and the result comes back as a sealed record.
  • As the operator, I want the deterministic substrate to fact-check whatever the model returns (atom-diff), so a probabilistic answer can't corrupt a sealed run.
  • As Joey and Fable 5, I want to optimize the tilde .md files together and convert them to .pi, then make them records in the .ids, so the corpus becomes an executable library, not documentation.
  • As the substrate steward, I want kastil-systems/a-d-d and every skill to run on this same engine, so the whole platform inherits LLM-free replay, not just the tildes.

4. Name It True

Literal names for each stage of the pipeline. The pipeline reads left to right; a tilde starts as a .md conversation and ends as a replayable card.

   │  DISPATCHER   = birt_dispatch() reads per-SLOT tier from .pi    │

   │  VERIFIER     = atom-diff: substrate fact-checks the model      │
   └───────────────┬───────────────────────────────┬────────────────┘
        Hot slot    │ Tier 0: pure C, $0            │ Cold slot: Tier 2/3
        replays ────┘                               └──▶ CLAUDE-RUN HOST
        LLM-free                                         (clauderun revived,
                                                          keyless via Vertex)
  1. Optimize — Joey + Fable 5 refine each tilde .md into its tightest form before sealing. Human-owned (Rule 10).
  2. .pi — the sealed pure-intent punch card. Frontmatter (name / protocol / DoR / DoD / verb / model / slots[] with per-slot tier + sub_task_hints) + scaffold. Literal, canon-exact.
  3. IDS record — the sealed store. RAW (append-only, one writer, the seed) + DERIVED (many, rebuilt by the decoder, versioned against the decoder not the data). Same raw + same decoder = byte-identical derived. No .ids file format; IDS is the umbrella.
  4. Decoder — nous understand(), the read side. This is the word Joey used; it already exists.
  5. Tail executor — the one shared chain-reaction program, extracted once.
  6. Dispatcher — birt_dispatch(), reads tier: per slot (the ~i's headline correction) and routes each slot to C99 or a model.
  7. Translator NEW — the dialect emitter. Takes one sealed .pi and emits the target model's wire dialect on the fly (Claude Messages, Vertex :rawPredict, the next model's schema). Literally “.pi first, export to model-specifics.” Name candidate for Joey to bless: emit / dialect / translator. Collision check: birt_translator.c exists (Anthropic-only) — this generalizes it, same name.
  8. clauderun (Cold host) — Claude Code in Cloud Run. Keeps Joey's name.
  9. Verifier — atom-diff. The deterministic substrate fact-checks the probabilistic model.

The card is the tier map, at slot granularity. The tail executor runs the mechanical protocol; the dispatcher walks slots[] — Hot slots run in C99, Cold slots go to the translator→clauderun→verifier loop. A tilde “cools” by a slot's tier dropping in its card — one number, operator-approved (Rule 10). No rebuild.

The runtime path of one Cold slot

  1. Dispatcher hits a tier: cold slot → asks the translator to emit the target dialect from the .pi + the slot's context (pre-computed by C99, so the model reads structure, not raw repo).
  2. Dispatch to clauderun (Cloud Run) — Agent SDK query(), autonomous CLAUDE.md, keyless via Vertex (gcp-bridge path). Returns the work + total_cost_usd.
  3. Verifier atom-diffs the result against ground-truth atoms; CONTRADICTED → reject/retry. GROUNDED → accept.
  4. Seal the (slot-context → result) pair as a DERIVED IDS record — the routing library warms by side-effect. Enough observations → the slot's tier drops toward Hot.

Boundaries (explicit out-of-scope)

  • OUT: the full 38-driver capability manifests (master-plan P14), ALF (P9/P13), silicon/biRT-v3. Far horizon.
  • OUT: the two floor=cold slots (~p Unknowns, ~patterns extract abstraction) — designed to stay Cold forever; the translator serves them, it does not eliminate them.
  • OUT: repo consolidation into kastil-systems/metal-desktop — that is parity-plan P1, a prerequisite tracked separately; this design targets the currently-canonical joeycastillo.us/metal-desktop tree and is portable to the consolidated repo.

Escape Routes load-bearing

  • Tier lives in frontmatter — if a Hot slot regresses, edit one number back to Cold. Instant, no rebuild. (Inherited from the Tier design.)
  • Decoder is deterministic + versioned — DERIVED IDS records carry the decoder version; a bad decoder rev is rebuilt from RAW, byte-identical. No data loss.
  • Cold host behind a dispatch seam — clauderun, Vertex, or a future runner swap at the dispatcher without touching any .pi. If clauderun locks up again, the seam falls back to the local Claude CLI.
  • The .pi is a superset of today — a card that fails to parse falls back to reading commands.md as Tier-0 does now. The migration cannot strand a tilde.
