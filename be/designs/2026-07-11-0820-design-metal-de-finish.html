1 · Need

The operator wants to USE the app now. Open metal.de, type the passphrase, and work: run tildes, produce real artifacts in a real project, close board items — without a login flow, without the relay being up, without a prime existing. Today the engine runs and the tail narrates; nothing the operator does in the cockpit lands a file in a real project yet. That is the whole gap.

Minimal complete usable state vs full parity

Minimal complete (this design's “done” line): passphrase → ~l a real project → work tildes execute → Cold slots answer via the free providers → a real artifact file lands in that project's be/ → the shared tail ships it (index, telemetry, board, commit) — all on this machine, $0 for the Hot legs, free-tier for the Cold ones.

Full parity (plan v2's 18-board line) additionally needs the mesh: catalog-over-wire (B2), FQDN identity (B4), relay tildes + Signals delivery (B6), the ~tlt metered cloud leg (B7's rent side). None of that gates daily use. The Finish draws the line explicitly and ships everything on the near side of it.

2 · Raw user stories

  • As the operator, I open metal.de, type goodtimes, and I'm in — no account, no login, no network beyond my own box.
  • As the operator, I ~l a real project of mine and the tail mutates it — board.md moves, reports save, commits land — instead of narrating what it would do.
  • As the operator, I run ~i / ~d / ~a / ~b and get a real HTML artifact file in my project's be/, indexed and committed, visible from the cockpit.
  • As the operator, I never wait on the relay, a prime, or the mesh — if a tail step needs the mesh (Signal delivery, Latchkey cap-URL when offline), it queues locally and tells me, and the work is still done.
  • As the operator, I can see at a glance which tildes are fully local and which are deferred-to-mesh — the app never fakes a mesh feature.
  • As the operator, I trust the guard: if no project is loaded, or the loaded path is the engine itself, nothing writes. Ever.

Piece 1 — loaded-project plumbing (the guard flip)

The guard exists; feed it. ~l <path> in the cockpit sets loaded_project after three checks, all local: (a) the path was explicitly given by the operator this session — never inferred, never persisted across restarts without re-confirmation; (b) it is a real git repo (or the operator confirms init); (c) it is not the engine — metal-desktop / metal trees are permanently observe-only. Pass all three and guard_mode=mutate, scoped to that one root: every tail write path-checks against loaded_project before touching disk. ~unload or a failed check drops straight back to observe. No project loaded = today's behavior exactly (narrate, zero writes).

Piece 2 — artifact tildes over free providers

Promote the work tildes from “Cold slots answer in chat” to “Cold slots fill a scaffold the tail ships.” Order of proof: ~i (inspect — reads the loaded project, cheapest judgment), then ~d, then ~a/~b. Each is its sealed .pi card: Tier-0 scaffold + save + index + commit from the tail; Cold judgment slots via the provider seam (5 free providers now; clauderun/Vertex later behind the same Slot — zero card edits). No relay anywhere on this path. Artifacts carry the Be template, the DoD checklist, the pubdate nav — indistinguishable from CE output because they run the same cards through the same tail.

Escape routes

  • Guard flip proves too eager or too shy — the three checks live in one function; retune there, never per-tilde. Two retunes = the load semantics were wrong, back to this design.
  • Free providers throttle or degrade on artifact-sized Cold slots — the Slot seam swaps in local CLI or paid providers without touching a card. Daily use survives on any one working provider.
  • Prime deploys early — nothing here blocks the horizon: the queue drains, B2/B6 pick up per plan v2, the passphrase gate simply gains a sibling (identity) rather than being replaced mid-daily-use.

6 · First move

One step crosses the line: the loaded-project set + one artifact tilde, tail shipping for real.

  1. Implement ~l <path> setting loaded_project with the three checks; flip guard_mode=mutate scoped to it (engine trees hard-excluded, path-check on every tail write).
  2. Run ~i against a real loaded operator project: Cold slots via a free provider, scaffold + save via the tail — a real be/builds/<stamp>-inspect-*.html lands ON DISK in that project, indexed, board-touched, committed by the tail.
  3. Exit proof: the file exists in the loaded project's repo with a tail-made commit; the cockpit displayed the chain as it ran; the engine tree shows zero writes; with no project loaded the same ~i still narrates only.

That single loop is the difference between “metal.de runs” and “the operator works in metal.de.” Everything else in The Finish widens this loop.
