nous.api — the mesh model front door

Route ALL model calls through one mesh surface. BYOK on the wire, blank = internal key, no key on the operator's box, primes placed near each provider's datacenter. This is an extraction, not an invention — the engine already runs in metal-de; the mesh already speaks the wire; the contract already exists as api.h. Companion inspect: be/plans/2026-07-11-0918-inspect-nous-api.html.

DESIGN — AWAITING APPROVAL

1 · Need

The locked decision says every model call goes through nous.api — four verbs (ask / judge / summarize / reconsider) served from the mesh, keys resolved in the mesh. Reality today (from the ~i):

  • The engine exists but lives on the box. metal-de serve.c (5,568 lines) implements task/judge/summarize with a 38-provider parallel fan-out — and resolves every key locally: resolve_key at serve.c:358 (user key → env → keys_builtin.h compiled into the binary). The moment that binary ships to any operator who isn't Joey, secrets ship with it. That is the exact thing the decision forbids.
  • The mesh exists but doesn't serve the verbs. 4 primes + 2 relays are live and sealed (MESH_STATUS.md 2026-05-30) but primes serve only /catalog/*. api.h is a complete contract with zero lines of implementation — skill.json declares "sources": ["api.c"] and api.c does not exist.
  • The cost of not doing it: every new surface (CE tildes, DE cockpit, Argus, anything on Purcius) re-solves provider access and re-plants keys on endpoints. One front door, one custody model, one place to meter — or N copies of the leak.

2 · Raw user stories

  • As an operator at the cockpit, I ask a question and get the 38-model fan-out back — with zero API keys stored, compiled, or env-set on my machine.
  • As a BYOK operator, I paste my own Anthropic/OpenAI/… key into the cockpit and my requests run on my key — carried per-request over the encrypted wire, RAM-only on the prime, never persisted, never logged.
  • As a free-tier operator, I leave the key field blank and the call silently falls through to the mesh's internal key. Blank = internal. No error, no setup.
  • As the mesh operator (Joey), I rotate a provider key in ONE sealed vault on the prime fleet — not in N binaries, N env vars, N users.dat files.
  • As a judge/summarize/reconsider flow, I run entirely on whatever key custody the original ask used — overrides forward through composed calls.
  • As a latency-sensitive call, my request executes on a prime placed near the provider's datacenter, so the mesh hop costs less than it saves.
  • As an offline / bridge operator, when the relay is unreachable, metal-de's local fan-out still works with my local keys — the mesh is the default, not a hostage-taker.

4 · Name it true

  • nous.api — it is the API of the nous mesh. Not “gateway”, not “proxy”, not “model-service”. The front door of the intelligence mesh.
  • The four verbs are the four words: ask, judge, summarize, reconsider. metal-de's legacy "task" WebSocket verb maps to wire verb ask at the cutover seam — the cockpit keeps its dialect, the wire speaks true.
  • Files say what they are: api.c routes, fanout.c fans out, providers.c knows providers, judge.c judges, summarize.c summarizes, reconsider.c reconsiders. One skill, one noun, no utils.c.
  • KeyOverride — it overrides a key. Blank = internal — the absence of an override IS the free tier; no flag, no mode, no config.

The five parts (build order)

  1. providers + fanout as real nous C skills. Lift g_defaults[] + handle_task/provider_thread out of serve.c into providers.c + fanout.c against the existing headers. Standalone, testable off the cockpit.
  2. judge / summarize port + reconsider build. De-globalize handle_judge/handle_summarize into judge.c/summarize.c; design + build reconsider.c (the one genuinely new verb) composing them.
  3. api.c verb router on relay/prime + deploy. Implement api_dispatch, wire it into the prime binary next to the catalog server, deploy to the sealed fleet. Primes now serve intelligence, not just /catalog/*.
  4. BYOK KeyOverride on the wire + prime key vault. Carry overrides as request triples; implement fanout_resolve_key precedence as designed; provision the sealed vault on the prime fleet (the custody move — keys leave the operator's box for good).
  5. Cockpit cutover. handle_task phase 3 swaps local fan-out for relay_request("ask"); blank-key fallback verified end-to-end; local fan-out demoted to offline/bridge fallback.

Boundaries

  • metal-de's LOCAL fan-out stays — as the offline/bridge fallback only. Default path is the mesh.
  • Wire protocol only into the substrate. Never HTTP/REST/SDK into the mesh; the deferred C# edge is a jacket outside the door, not a second door.
  • C99 we own. api.c, fanout.c, providers.c, judge.c, summarize.c, reconsider.c — all pure C99. C# appears only if/when the foreign-facing REST jacket ships.
  • api.c is thin. Four verbs, nothing else. Dev-loop, /search, /learn stay engine-only (api.h:58).
  • a-d-d is the spec. Where the living table outgrew providers.h, the spec updates flow up first (Rule 11) — approval required before the header changes.

6 · First move

The smallest proof: one question, one provider, one prime, zero keys on the box.

  1. Extract providers.c + fanout.c from serve.c against the existing headers (part 1) — compile standalone, smoke locally.
  2. Stub api.c with only api_ask routing to fanout_ask; deploy to ONE prime (Ashburn elite) beside the catalog server.
  3. Plant one provider key (Gemini free-tier) in that prime's sealed vault. Unset it everywhere on the dev box.
  4. From the cockpit, send wire verb ask with a blank key through relay.3-metal.net; receive the answer triples back and render them.

Green means: the extraction compiles, the wire carries the verbs, the round-trip payload fits the 0xCA envelope (or tells us it needs chunking now), and blank = internal works with the key living only in the mesh. That single thread de-risks all five parts before any board gets points. Per Rule 13, verification runs from inside GCP (SSH the prime, peer-curl the wire port) — not from this box.
